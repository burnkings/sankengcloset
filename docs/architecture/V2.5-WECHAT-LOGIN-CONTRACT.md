# 微信登录 — 前后端契约与实测结论

> 更新日期：2026-09-25
> 一句话结论：**后端接口已实现且是公开路由，前端已按平台就绪；唯一卡住的是微信「IP 白名单」没加后端服务器公网 IP。**
> 另外提醒：你现在给的这对凭据是**小程序**的，**App 端微信登录用不了这一对**（见 §5）。

## 1. 线上实测（2026-09-25，只读探针）

用 `node scripts/check-wechat-login.js` 复现：

| # | 探针 | 结果 | 结论 |
|---|---|---|---|
| 1 | 直连微信 `jscode2session`（本机 IP + 你的 AppID/Secret + 假 code） | `{"errcode":40164,"errmsg":"invalid ip 112.0.140.2 ... not in whitelist"}` | **IP 白名单拦截**。微信先查 IP 再查 Secret，所以这一条**不能证明 Secret 对不对** |
| 1b | 同上，但把 AppID 改成一个假的 | `{"errcode":40013,"errmsg":"invalid appid"}` | 反证：**你的 AppID `wx976f673896c8b565` 有效**（错 AppID 会先报 40013） |
| 2 | `POST /api/v1/sessions/wechat`，空 body `{}` | `400 VALIDATION_FAILED — expected string, received undefined` | **后端是公开路由且做参数校验** ✅（登录接口本该无需鉴权） |
| 3 | 同上，body `{"code":"<假 code>"}` | `401 UNAUTHORIZED — 登录凭证已失效，请重试` | **后端 code2Session 代理已实现** ✅：假 code 被正确拒绝 |

> ⚠️ 由此更正一条旧判断：此前记录的「`/api/v1/sessions/wechat` 返回 401 = 接口在但没配 AppID/Secret」是**错的**。
> 401 是**假 code 被微信拒绝后的正常映射**；`{}` 返回 400 而不是 401，说明路由没有被鉴权中间件挡住。

**唯一待办（需你操作）**：微信公众平台 → 开发管理 → 开发设置 → **IP 白名单**，把
**后端服务器公网 IP** 加进去。不加白名单，后端从服务器调 `jscode2session` 同样会收到 40164，
真机登录就会一直提示「登录凭证已失效，请重试」——这与「Secret 错」的现象一模一样，容易误判。

## 2. 链路

```
小程序端                       后端 api.sankengcloset.icu              微信
wx.login()  ──code(5min)──▶  POST /api/v1/sessions/wechat
                              code2Session(appid, secret, code)  ──▶  jscode2session
                                                              ◀──  openid / unionid / session_key
                              upsert user(openid) → 签发 accessToken/refreshToken
         ◀── { accessToken, refreshToken, userId }  ────
GET /api/v1/me (Bearer) ──▶   返回昵称/头像 → 落本地会话
```

**AppSecret 只出现在「后端 → 微信」这一跳**，永远不经过客户端。

## 3. 后端要求

### 3.1 环境变量（命名与 `.env.local` 对齐）

| 变量 | 值来源 | 说明 |
|---|---|---|
| `WECHAT_MP_APPID` | `.env.local` | `wx976f673896c8b565` |
| `WECHAT_MP_APP_SECRET` | `.env.local`（**不进版本库**） | code2Session 用 |

`.env.local` 已被 `.gitignore` 的 `.env.*` 规则忽略。部署时把这两个变量写到服务器环境（或密钥管理服务），
**不要**写进任何前端文件、不要写进文档、不要提交。

### 3.2 接口

`POST /api/v1/sessions/wechat` — **必须公开**（不能挂鉴权中间件）

请求：

```json
{ "code": "wx.login 返回的 code（5 分钟有效、一次性）", "deviceId": "可选" }
```

成功 `200`：

```json
{
  "requestId": "req_01H...",
  "data": { "accessToken": "...", "refreshToken": "...", "userId": "usr_xxx" }
}
```

失败映射（客户端 `wechatLoginErrorMessage()` 已按此分流）：

| 场景 | 建议状态码 | 客户端提示 |
|---|---|---|
| 缺 `code` / 类型不对 | `400` | 「微信登录参数有误，请更新到最新版本后重试」 |
| code 无效 / 已用过 / 已过期 | `401` | 「微信授权已失效，请重新点击登录」 |
| 微信侧 `40164`（IP 未白名单）、`-1`（系统繁忙） | `503` | 「登录服务暂时不可用，请稍后重试」 |
| 路由不存在 | `404` | 「微信登录服务尚未上线，请稍后再试」 |

服务端务必把微信的 `errcode` 打到日志里（当前 401 文案过于笼统，无法区分"code 过期"和"IP 未白名单"，
这次排查就是被这句话绕了一圈）。

### 3.3 会话

- `openid` 唯一；有 `unionid` 时一并存（未来接 App 端 / 公众号可打通同一个人）；
- `session_key` **不要**返回给客户端，只存服务端（解密用）；
- `accessToken` 短期、`refreshToken` 长期，续期走已有的 `POST /api/v1/sessions/refresh`。

## 4. 前端实现（已完成）

| 环节 | 位置 | 行为 |
|---|---|---|
| AppID 常量 | `config/wechat.uts` | `WECHAT_MP_APPID = 'wx976f673896c8b565'`，由单测守护与 `manifest.json` 一致 |
| 登录动作 | `stores/session-store.uts` → `loginWithWechat()` | `uni.login({provider:'weixin'})` 拿 code → `POST /api/v1/sessions/wechat` → 存 token → `GET /api/v1/me` 补昵称头像 |
| 平台判定 | 同文件 `wechatLoginSupported()` | 小程序端看 `WECHAT_MP_LOGIN_ENABLED`；App 端看 `WECHAT_APP_LOGIN_CONFIGURED` |
| 错误分流 | 同文件 `wechatLoginErrorMessage()` | 按 400/401/404/5xx/网络失败给可操作文案 |
| 登录入口 | `pages/profile/index.uvue` → `openLoginOptions()` | 不具备条件时**不显示「微信登录」这一项**，避免对必然失败的按钮白点 |

`manifest.json` 的 `mp-weixin.appid` 已是 `wx976f673896c8b565`，无需改动。

## 5. App 端（Android / iOS）差异 —— 别复用小程序凭据

小程序登录和 App 微信登录是**两套完全独立的凭据**：

| | 小程序端 | App 端 |
|---|---|---|
| 平台 | 微信公众平台（mp.weixin.qq.com） | **微信开放平台**（open.weixin.qq.com）· 移动应用 |
| AppID | `wx976f673896c8b565`（已配） | **另一个** AppID，需先创建「移动应用」并通过审核 |
| 额外要求 | 无 | 登记**包名 + 应用签名**（与 `manifest.json` 的 `appid`、`release.keystore` 指纹一致） |
| 客户端调用 | `wx.login()` 拿 code | `uni.login({provider:'weixin'})`，需在 `manifest.json` 配 `app-plus.distribute.sdkConfigs.oauth.weixin` |

在小程序 AppID/Secret 上做 App 端登录**一定失败**。所以：

- 现在给的是小程序凭据 → **小程序端可以立刻跑通**（白名单加完即可）；
- App 端要另开开放平台移动应用，审核通过后把 `config/wechat.uts` 的 `WECHAT_APP_LOGIN_CONFIGURED` 改为 `true`，
  并在 `manifest.json` 里补 SDK 配置。

## 6. 验收

```bash
node scripts/check-wechat-login.js
# 期望：微信直连 PASS / 路由公开 PASS / 后端代理 PASS
#   → 微信直连要到 PASS，必须先做 IP 白名单；加白后它会返回 40029 (invalid code)，即全部就绪
```

真机冒烟：小程序端「我的」→ 点登录卡片 → 应弹出「微信登录 / 仅在本机使用」两项 → 选微信登录 →
成功进入并显示「ID: usr_xxx」（而不是「本机数据」）。

## 7. 安全红线

1. **AppSecret 绝不进客户端**（小程序包 / APK 都能被反编译提取，微信明令禁止并会处罚）；
2. 前端仓库只放 AppID（`config/wechat.uts`），Secret 只放 `.env.local` / 服务器环境变量；
3. `session_key` 不下发；日志里不打印 `secret`、`accessToken`、`openid` 全量；
4. `code` 一次性、5 分钟过期 —— 后端换到 `openid` 后即失效，重试必须重新 `wx.login`。
