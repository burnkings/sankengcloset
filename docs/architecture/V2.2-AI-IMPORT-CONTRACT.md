# V2.2 AI 辅助导入服务契约

## 1. 核心原则

- 模型输出是 suggestion，不是业务实体。
- 用户确认是独立 confirmation 事件，必须保存修正前后差异。
- 图片进入对象存储，API 与同步队列只传 objectKey。
- 模型名称、版本、请求 ID、证据和置信度必须可审计。
- 低置信度字段不得自动覆盖用户已有数据。

## 2. 端点

- `POST /api/v1/uploads:prepare`：获取图片上传凭证。
- `POST /api/v1/ai/import-tasks`：以 objectKey 创建识别任务。
- `GET /api/v1/ai/import-tasks/{taskId}`：轮询 pending / processing / ready / failed。
- `POST /api/v1/ai/import-tasks/{taskId}/confirm`：提交用户最终确认值、目标类型和幂等 opId。
- `DELETE /api/v1/ai/import-tasks/{taskId}/source`：按隐私策略提前删除源图。

创建任务返回 `202 Accepted`。任务结果不得直接创建衣橱、心愿或购买记录。

## 3. 识别结果

{
  "taskId": "ait_...",
  "state": "ready",
  "model": { "provider": "replaceable", "name": "vision", "version": "..." },
  "suggestion": {

    "brand": "",

  "confidence": 0.74,

客户端金额继续使用整数分；当前界面输入元，确认 Adapter 负责转换。

## 4. PostgreSQL

| 表 | 关键字段 | 约束 |
|---|---|---|
| ai_import_tasks | id, user_id, device_id, object_key, state, request_id, created_at, expires_at | user_id/state 索引 |
| ai_import_suggestions | task_id, model_name, model_version, suggestion_json, confidence, evidence_json | task_id unique |
| ai_import_confirmations | id, task_id, user_id, target_type, target_id, confirmed_json, correction_json, op_id | unique(user_id, op_id) |
| media_objects | id, owner_user_id, object_key, purpose, retention_until, deleted_at | object_key unique |

## 5. Mock 与 Remote 切换

当前 Mock Adapter：

- 示例图返回固定高置信度演示草稿。
- 用户真图返回低置信度“待确认单品”，绝不推断品牌。
- 延迟、离线和失败沿用 V2.1 RuntimeConfig。

Remote Adapter 接入后保留 `AiImportTask` 与页面交互，只替换 Service 内部实现。

## 6. 隐私

- 上传前显示用途；确认后允许删除原图。
- 不做人脸、年龄、性别、身材或身份推断。
- 日志不记录本地路径、临时上传 URL、Token。
- 原图保留期与用户删除请求必须可配置、可审计。
