# 三坑绮橱 V2.3 后端落地 Runbook

## 已直接完成

- Fastify + TypeScript API 服务。
- PostgreSQL 初始迁移与开发种子数据。
- 开发 JWT 登录；生产环境自动关闭开发登录。
- Feed 与商品详情真实 HTTP 契约。
- 批量同步操作的用户级 opId 幂等回执。
- 图片上传准备与开发环境本地对象存储。
- AI 导入任务、查询、人工确认后写入衣橱/心愿单。
- OpenAPI UI、Docker Compose、CI、类型检查和接口测试。

## 需要用户或 Hermes 完成

1. 创建独立私有仓库 `burnkings/sankengcloset-api`，后续将 `backend/` 目录迁出。
2. 准备一台测试服务器、域名和 HTTPS；微信小程序正式环境不能使用裸 HTTP。
3. 创建测试 PostgreSQL 数据库并使用强密码，不使用 Compose 示例密码。
4. 在微信公众平台配置合法 request/upload/download 域名。
5. 提供微信小程序 App ID 与服务器端 App Secret；Secret 只存服务器环境变量。
6. 选择对象存储（腾讯云 COS、阿里云 OSS 或 S3 兼容服务），替换本地存储适配器。
7. 选择视觉模型/OCR 供应商后实现 remote provider；上线前保留人工确认。
8. 配置 GitHub Actions Secrets 与部署流程。
9. 增加内容采集与审核服务；它与用户主库分离，未经审核的数据不能直接进入 Feed。

## 推荐部署顺序

1. 测试域名 + PostgreSQL + API 容器。
2. 开发登录联调 Feed 和同步队列。
3. 微信 code2Session 登录。
4. 对象存储与 AI 图片导入。
5. 客户端 Remote Adapter 灰度开关。
6. 内容采集、审核后台与价格提醒任务。

## 发布前硬门禁

- 生产环境不能开放 `/sessions/dev`。
- JWT Secret 至少 32 位随机值且不可提交 Git。
- 微信 App Secret、数据库密码、对象存储密钥不得写入客户端。
- API 全部 HTTPS；CORS、限流、日志脱敏、备份恢复演练完成。
- 用户删除与导出、图片保留期、AI 纠错记录可审计。
- 外部购买跳转必须明确标注，不能让用户误以为本应用参与交易。
