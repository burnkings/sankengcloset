# V2.1 服务端与数据库契约

> 目标：让当前 Mock Adapter 能被真实后端替换，而不改页面、FeedItem 或同步操作语义。

## 1. API 约定

Base path：`/api/v1`

成功响应：

```json
{
  "requestId": "req_...",
  "data": {},
  "page": {
    "nextCursor": "opaque-cursor",
    "hasMore": true,
    "totalHint": 120
  }
}
```

失败响应：

```json
{
  "requestId": "req_...",
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "字段不符合要求",
    "retryable": false
  }
}
```

稳定错误码：`OFFLINE`、`UNAUTHORIZED`、`NOT_FOUND`、`CONFLICT`、`RATE_LIMITED`、`VALIDATION_FAILED`、`SERVER_ERROR`。

所有时间使用 ISO 8601 UTC；金额使用整数分；ID 为服务端生成的不可枚举字符串。客户端 `opId` 在用户范围内全局唯一。

## 2. 首批端点

### 会话

- `POST /sessions/wechat`：微信 code 换取账号会话。
- `POST /sessions/refresh`：刷新短期 access token。
- `DELETE /sessions/current`：退出当前设备。
- `GET /me`：个人资料与服务能力。
- `POST /me/local-assets/import`：导入本地资产清单，必须支持幂等 opId。

### Feed 与发现

- `GET /feed?channel=&category=&cursor=&limit=`
- `GET /products/{id}`
- `GET /brands/{id}`
- `GET /release-events?from=&to=&cursor=`
- `GET /search?q=&type=&cursor=`

Feed 返回客户端现有 `FeedItem` 展示协议；后端实体不得直接泄漏给页面。

### 用户关系

- `PUT /me/favorites/{productId}`
- `DELETE /me/favorites/{productId}`
- `PUT /me/brand-follows/{brandId}`
- `DELETE /me/brand-follows/{brandId}`
- `PUT /posts/{postId}/like`
- `DELETE /posts/{postId}/like`

以上写接口均接收 `Idempotency-Key: opId`。

### 晒搭

- `POST /outfit-posts`
- `DELETE /outfit-posts/{id}`
- `GET /outfit-posts?topic=&category=&cursor=`
- 图片先通过对象存储上传凭证接口获取临时上传地址。

### 个人资产

- `GET|POST /me/wardrobe-items`
- `GET|PATCH|DELETE /me/wardrobe-items/{id}`
- `GET|POST /me/purchase-records`
- `GET|PATCH|DELETE /me/purchase-records/{id}`
- `GET|POST /me/reminders`
- `GET|PATCH|DELETE /me/reminders/{id}`
- `PUT /me/budget`

购买记录是用户在外部官方渠道的决策记录，不是本应用订单或支付凭证。

### 通知与同步

- `GET /notifications?type=&cursor=`
- `PUT /notifications/{id}/read`
- `PUT /notifications/read-all`
- `POST /sync/operations:batch`
- `GET /sync/checkpoint`

批量同步响应必须逐条返回 accepted / rejected / conflict，不可只返回整批成功。操作按 `createdAt` 顺序应用；create/update/upsert 携带实体快照或动作 payload，delete 可为空。图片只传对象存储 key，不将 base64 图片放入批量同步。

## 4. MongoDB 的合适位置

MongoDB 可作为可选的采集候选库：

- 原始公开页面快照。
- AI 尚未归一化的字段。
- 多来源去重前的候选文档。
- 审核前内容与解析日志。

它不应成为收藏、关注、预算、购买记录、提醒和幂等同步操作的唯一主库。这些数据需要唯一约束、关联查询、事务和清晰迁移，PostgreSQL 更稳妥。

## 5. 本地迁移流程

1. 用户首次真实登录。
2. 客户端生成本地资产清单与稳定 opId。
3. 服务端按实体自然键/本地 ID 去重。
4. 返回 accepted、conflict 与服务端 ID 映射。
5. 客户端仅在收到回执后更新 checkpoint；失败操作继续保留。
6. 图片上传与结构化记录分开重试。
7. 退出登录不删除本地数据；换账号时必须要求用户确认数据归属。

## 6. 安全与审计

- Token 不写入日志、文档或同步 payload。
- 来源抓取凭据、Cookie 与验证码处理不进入客户端。
- 所有公开内容保留来源、抓取时间、原始发布时间与审核状态。
- 用户删除、导出和纠错保留可审计事件。
- 生产环境禁止客户端切换 Mock/Remote；运行模式由构建配置锁定。


## 7. 当前客户端同步实体映射

| entityType | 写入来源 | payload |
|---|---|---|
| favorite / brand_follow / post_like | 内容资产 Store | 关系状态由 action 表达 |
| outfit | 晒搭发布与删除 | 分类、话题、文案；图片后续独立上传 |
| wardrobe_item | 衣橱新增、编辑、收藏、删除 | create/update 携带结构化快照 |
| purchase | 外部购买记录新增、编辑、删除 | create/update 携带结构化快照 |
| reminder | 提醒新增、编辑、完成、删除 | create/update 携带结构化快照或状态动作 |
| budget | 月预算设置 | monthlyLimit 与 alertPercent |
| notification_read | 单条或全部已读 | read / readAll |
| local_asset_bundle | 首次登录本地资产迁移 | 资产类型清单 |

真实 Remote Adapter 接入时必须校验 payload schema，并将客户端本地 ID 映射为服务端 ID；Mock 队列只验证持久化、离线重试与幂等边界。
