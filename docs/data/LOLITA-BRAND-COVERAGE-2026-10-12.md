## ⚠️ 先说口径：平台内现在**没有**能代表真实热度的数据

| 指标 | 现状 | 能说明什么 |
|---|---|---|
| 品牌收藏（`BRAND_FOLLOW`） | **0** | 无信号 |
| 商品收藏（`PRODUCT_FAVORITE`） | **0** | 无信号 |
| 商品浏览（`view_count`） | 个位数（最高 90） | 无信号 |
| 商品入库时间 | 绝大多数是 **10-07 那一次批量导入** | 「30 天新增」= 商品数，**无区分度** |

⇒ **不能拿平台数据宣称「热度排名」**（会把「我们采了多少」包装成「市场多热」）。
所以这份表用的是「**外部公开来源点名 × 我们覆盖**」的交叉法：外部公认的头部，我们有没有。

## 附：可复现脚本

```js
// 在服务器项目目录下执行（模块按 CWD 解析）
const fs = require('fs')
const postgres = require('postgres')
const url = fs.readFileSync('.env.production', 'utf8').match(/^DATABASE_URL=(.*)$/m)[1].trim().replace(/^["']|["']$/g, '')
const sql = postgres(url, { max: 1 })
// LOLITA 品牌按商品数排序（含收藏/浏览/最近更新/30天新增）
const rows = await sql`
  select b.name,
         (select count(*)::int from user_interactions ui where ui.brand_id = b.id and ui.kind = 'BRAND_FOLLOW') as followers,
         count(p.id)::int as products,
         coalesce(sum((select count(*)::int from user_interactions w where w.product_id = p.id and w.kind = 'PRODUCT_FAVORITE')), 0)::int as fav_sum,
         coalesce(sum(p.view_count), 0)::int as view_sum,
         max(p.updated_at)::date as last_update
    from brands b left join products p on p.brand_id = b.id and p.deleted_at is null
   where b.category = 'LOLITA' and b.deleted_at is null and b.brand_status = 'active'
   group by b.id, b.name order by products desc, fav_sum desc`
```
