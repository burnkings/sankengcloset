# Product V2.4 — 真实数据闭环

## 目标

在不破坏本地演示能力的前提下，让 UniApp X 客户端真正连接 V2.3 Fastify 服务。该版本解决“后端已启动，但前端仍是 Mock”的断点，并为 PostgreSQL、对象存储和正式微信登录预留稳定边界。

## 本版本交付

- 本地演示 / 远程服务显式切换；远程失败不伪装成功。
- API Base URL 持久化、地址规范化、`/health` 连接诊断。
- 统一 `apiGet` / `apiPost`，自动携带 Bearer Token，并解析统一错误信封。
- 首页 Feed 接入 `GET /api/v1/feed`，服务端分页映射为既有 `FeedItem`。
- 开发体验账号接入 `POST /api/v1/sessions/dev`，保存访问与刷新令牌。
- 访问令牌过期后使用刷新令牌续期，并仅重放一次原请求。
- 离线队列接入 `POST /api/v1/sync/operations:batch`，仅按 accepted 回执删除操作。
- 切换数据模式或 API 地址时清理跨环境会话，避免令牌串用。
- 真机网络边界提示：手机不能使用服务器的 `127.0.0.1`。

## 明确边界

- `/sessions/dev` 只用于非生产体验；正式环境切换 `/sessions/wechat`。
- 小程序体验版可使用已关闭域名校验的开发工具或 HTTPS 隧道；正式发布必须配置微信合法域名。
- 图片二进制上传仍保留本地安全草稿。对象存储、CDN 与 `uni.uploadFile` 完整链路进入 V2.5。
- Remote 模式不自动回退 Mock，避免真实环境故障被假数据掩盖；用户可手动切回本地演示。

## 验收顺序

1. 在“我的 → 同步与连接”选择远程服务，填写服务器同网段地址或 HTTPS 隧道地址。
2. “保存并检查连接”显示 `sankengcloset-api`。
3. 返回首页后 Feed 来自 Fastify Memory/PostgreSQL 驱动。
4. 在账号页完成远程开发登录。
5. 产生一条收藏/关注操作并同步；服务端 accepted 后本地队列清空。
6. 断开服务后再次同步，操作仍保留且重试次数增加。
