# 三坑绮橱 V2.0 内容闭环版交付计划

> 状态：功能候选（等待 Hermes 双平台门禁）  
> 分支：`feature/v2.0-content-loop`  
> 上游：`feature/v2-final-experience`

## 1. 版本目标

V2.0 不以“增加多少页面”为完成标准，而以用户是否能从内容走到行动、再回到个人资产为标准。

核心循环：

1. 在首页、发现或晒搭中发现商品、品牌与搭配。
2. 收藏商品、关注品牌、保存穿搭或设置发售提醒。
3. 用绮灵 AI 对收藏、预算、衣橱和发售节点进行决策。
4. 外跳官方渠道购买后，在购买记录与个人衣橱继续管理。
5. 用户可发布美照并进行轻量互动，但不建设重型社区。

## 2. V2.0 完成范围

### 2.1 内容资产闭环

- 商品收藏与取消收藏持久化。
- 品牌关注与取消关注持久化。
- 收藏页展示真实商品与品牌资产。
- 晒搭支持多条本地发布与旧数据迁移。
- 个人中心展示真实内容资产数量。
- 衣橱支持新增、编辑、照片持久化与删除，不再是只读 Mock。

### 2.2 发售与消费决策闭环

- 商品详情可直接预填发售/尾款提醒。
- 商品详情可预填购买记录，但购买仍发生在外部官方渠道。
- 提醒与购买表单升级到 V2 视觉系统，移除 Emoji、`gap` 和通用 Toast。
- 发售阶段、截止时间、收藏与提醒形成一致状态表达。
- 月预算与提醒阈值本地持久化，并按当月购买记录计算承诺金额。

### 2.3 绮灵 AI 决策闭环

- AI 输入按意图分流，而不是所有问题返回同一句话。
- 衣橱搭配、平替雷达、收藏画像、预算守门、发售雷达使用不同数据源与结果结构。
- 图片识款只负责图片采集与识别任务入口，不伪造识别结果。
- 本地规则引擎结果明确标注为“本地分析”；远端模型接入后替换引擎，不改页面契约。

### 2.4 晒搭轻互动闭环

- 多条本地晒搭持久化。
- 帖子点赞状态持久化。
- 本人内容可删除。
- 预留评论数据契约；不做群聊、陌生人私信和泛娱乐信息流。

### 2.5 账号与数据边界

- 未登录与本地登录态清晰区分。
- 未接入服务端前不伪造云同步成功。
- 收藏、关注、晒搭等内容资产均可被本地账号页面统计。

## 2.6 已完成的静态门禁

- 新增与重写文件无 `gap`、`calc()`、原生 `uni.showToast`、页面重载或 Web DOM API。
- 商品提醒、购买记录、衣橱和预算路由均已注册。
- 搜索页回填关键词不自动获取焦点；深色模式不重载页面或重置滚动位置。
- 内容少于一屏时不显示“上拉加载更多”。
- 以上是仓库静态检查，不替代 HBuilderX、微信真机和 Android 真机门禁。

## 3. 明确不做

- 应用内支付、自营库存、售后、物流和自动下单。
- 群聊、重型社区、泛娱乐推荐和陌生人社交。
- 无来源的价格保证、虚假价格预测或伪造 AI 识别结果。
- 为兼容旧 Dashboard 而破坏内容首页。

## 4. 平台验收

### 微信小程序

- HBuilderX CLI 编译、vendor patch、require 路径校验全部通过。
- 首页双列分页、搜索、收藏、关注、晒搭与深色模式真机通过。
- 连续发布两条晒搭后重启，内容仍可查看。

### Android App

- Vapor 开启；正式 Feed 使用 `list-view/list-item`。
- 30/100/300 卡滚动、图片失败、返回位置与弱网门禁通过。
- 相册/相机、文件持久化、系统栏和底部导航真机通过。

### HarmonyOS / iOS

- 保留条件编译与 API 兼容，不引入平台私有依赖。
- HarmonyOS 作为后续优先验证平台；iOS 优先级最低。

## 5. 版本退出条件

- 四个闭环均有真实状态变化，不是静态 Mock 按钮。
- 所有新增页面遵循 V2 token、间距、反馈与深色模式。
- PR #1 先完成基础体验门禁；PR #2 再完成 V2.0 双平台门禁。
- 门禁通过前保持 Draft，不删除用于回滚与对照的远程分支。
