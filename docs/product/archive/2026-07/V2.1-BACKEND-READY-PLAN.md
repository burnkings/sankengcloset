# 三坑绮橱 V2.1 后端就绪版交付计划

> 状态：功能候选，等待 Hermes 全平台门禁  
> 分支：`feature/v2.1-backend-ready`  
> 基线：V2.0 merge commit `fb67796`

## 1. 版本目标

V2.1 不急于绑定某一家后端或数据库，而是先把客户端从“页面直接读写本地数据”升级为：

> 页面 → Store → Service/Gateway 契约 → Mock/Remote Adapter → 本地缓存与同步队列

因此现在可以完整演示账号、通知、分页、离线操作和同步状态；未来接入 Node/Python/UniCloud 及 PostgreSQL/MongoDB 时，只替换 Adapter，不重写页面和业务状态。

## 2. 本版完成范围

### 2.1 运行环境与 API 契约

- 统一运行模式：local / mock / remote。
- 统一错误码、请求 ID、游标分页和时间字段。
- Mock 支持延迟、离线、可恢复失败和分页。
- Remote Adapter 只保留显式边界；未配置服务地址时绝不发起伪请求。

### 2.2 模拟账号与本地数据归属

- 游客与体验账号成为独立 Store，不再是页面内布尔值。
- 登录后生成稳定 userId、accessToken 占位和设备 ID。
- 首次登录展示“本地资产待同步”，不伪造云端已经保存。
- 退出登录不删除本地衣橱、订单和内容资产。

### 2.3 离线优先同步队列

- 收藏、关注、点赞、晒搭发布/删除、通知已读、心愿单、衣橱、购买记录、提醒与预算写操作进入 Operation Queue。
- 操作包含 opId、entityType、entityId、action、payload、createdAt、retryCount。
- Mock 同步可真实消费队列并记录最后成功时间。
- 离线或失败时保留队列，允许手动重试。
- 冲突策略先采用客户端时间 + 幂等 opId；服务端接入时升级为版本号/ETag。

### 2.4 通知中心

- 统一发售、降价、互动和系统通知模型。
- 支持分类、已读/未读、全部已读。
- Mock 通知可从收藏、关注和提醒状态生成。
- 暂不声称已经接入系统推送；后端接入后由通知 Gateway 替换数据源。

### 2.5 Feed 数据访问层

- 首页 Store 不再直接依赖 MockFeedRepo。
- FeedService 返回稳定的 cursor page 契约。
- V2.0 Mock 数据继续作为本地 Adapter，页面行为保持不变。
- 服务端接入时保持 FeedItem 展示协议不变。

## 3. 数据库映射原则

客户端契约保持数据库中立，但后端默认建议 PostgreSQL：

- 商品、品牌、系列、发售事件、用户关系和提醒具有明确关联和事务边界。
- JSONB 可保存来源快照、AI 证据和可变扩展字段。
- 游标分页、唯一约束、幂等操作和审核流水更适合关系模型。
- MongoDB 可用于原始采集快照或内容候选库，但不建议作为用户关系和交易决策数据的唯一主库。

建议后端分层：

- PostgreSQL：用户、商品、品牌、发售、收藏、关注、提醒、衣橱、购买记录、同步操作。
- 对象存储：商品图、晒搭图、导入截图。
- Redis（规模上来后）：Feed 缓存、限流、幂等键、短期任务状态。
- MongoDB（可选）：未经审核的原始抓取文档与 AI 解析中间结果。

## 4. 明确不做

- 不实现生产账号密码、短信验证码或微信真实登录。
- 不实现真实云端同步、系统 Push 或服务端价格抓取。
- 不伪造 AI 识款、价格预测和云端成功提示。
- 不引入支付、物流、群聊和陌生人私信。
- 不在本版绑定特定云厂商。

## 5. 退出条件

- 核心页面不直接感知 Mock/Remote 差异。
- 体验账号、通知中心、同步中心可完整操作。
- 离线操作可排队、重试并持久化。
- 首页分页通过 FeedService 契约工作。
- 新页面遵循 V2 token、深色模式、App/微信导航与反馈规范。
- Hermes 完成 mp-weixin、Android Vapor 与持久化重启门禁。


## 6. 当前交付状态

- 已建立 local / mock / remote 运行边界；remote 无地址时安全回退 Mock。
- 已建立 FeedService、会话 Store、通知中心和持久化同步队列。
- 已覆盖内容互动、心愿单与个人数据域的所有现有写入口。
- 新增账号、本地资产、通知中心、同步中心三个可操作页面。
- 已补齐服务端 API、PostgreSQL 表映射和 MongoDB 可选边界。
- 本分支只完成静态契约与客户端实现；HBuilderX、微信真机、Android Vapor 和重启持久化仍由 Hermes 执行。
