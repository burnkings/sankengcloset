## A. 合规硬缺口（上架/审核前必须补）

### A1. 账号注销没有入口 ★★★

- 现状：`pages/about/legal-content.uts` 第 174 行明确承诺「**您可申请注销账号**，注销后我们将删除或匿名化您的个人信息」，第 83 行也写了用户可随时通过注销账号停止使用。
- 但全站**没有任何 UI 入口**（`grep -rn "注销账号" pages/ --include=*.uvue` 结果为空；设置项里只有深色模式/推荐偏好/通知设置/屏蔽品牌/帮助与反馈/清理缓存/关于/退出登录）。
- 风险：国内应用商店审核与 PIPL 都对「注销账号」有明确检查项；文本承诺 + 无入口是最典型的驳回原因。
- 建议做法：`pages/preferences/` 下新增「账号与安全」页，提供「注销账号」二次确认（写明后果：数据不可恢复、多久生效），随后清本地数据并 `reLaunch` 回首启页。
- 可简单修：**否**（涉及注销流程与后端接口约定，建议先定接口再动手）。

### A2. 没有展示 App 备案号 ★★★

- 现状：全仓库检索「备案」零结果。
- 风险：2023 年起国内 App 需完成工信部备案，并**在应用内显著位置展示备案号**。
- 建议做法：`pages/about/index.uvue` 增加一行「备案号」并在隐私政策末尾列明；备案号与 `LEGAL_ENTITY` 一起纳入 `legal-content.uts`（该文件已标了「待运营补充」占位，可一并填）。
- 可简单修：**是**（占位一行文本，等运营给号）。

### A3. 隐私政策缺少第三方 SDK 清单 ★★ → ✅ 已补（见 §F）

- 现状：隐私政策共 11 章（引言/收集的信息/使用目的/存储/共享与披露/个性化推荐/您的权利/未成年人保护/信息安全措施/政策更新/联系我们），**没有第三方 SDK 目录章节**。
- 但项目确实使用微信登录（`session-store` 的 `loginWithWechat`）与 uni-app x 原生能力，按规范需要列明 SDK 名称、提供方、收集信息与用途。
- 建议做法：在隐私政策「五、信息的共享与披露」之后新增「第三方 SDK 目录」章节；表格列：SDK 名称 / 提供方 / 使用目的 / 收集的信息 / 隐私政策链接。
- 可简单修：**是**（纯文本补充，但内容需运营/法务确认）。

### A4. 隐私政策缺少系统权限调用清单 ★★ → ✅ 已补（见 §F）

- 现状：只有通知权限的运行时提示（`pages/preferences/notification.uvue` 第 74 行），政策正文**没有权限清单章节**。
- 实际会触发的权限至少包括：相册/相机（`purchase/import` 截图识别、`wardrobe/edit` 加照片、`share/create` 发布穿搭、`profile/edit` 换头像）、通知（尾款/到货/发售提醒）。
- 建议做法：新增「系统权限调用清单」章节，逐条写「权限 / 使用场景 / 拒绝后的影响（可手动录入，不影响浏览）」。
- 可简单修：**是**（纯文本）。

## B. 产品功能缺口（产品方向已定义，但未实现或未闭环）

### B1. 商品对比 / 比较 ★★ → ✅ 已实现（见 §F）

- `PRODUCT-DIRECTION-CURRENT.md` 把主链路写成「…收藏追踪 → **比较/决策** → 购买外跳…」，但全仓库检索「对比 / 比较」在 `pages/` 下**零结果**，没有任何对比功能。
- 三坑用户的真实决策场景（同款比价、定金/全款/尾款对比、尺码对比）恰好依赖这个。
- 建议做法：先在收藏页做「勾选 2–3 件 → 对比抽屉」轻量版（只比：图片、价格构成、发售状态、尺码/颜色），不做独立页。

### B2. 搜索历史 ★ → ❌ 盘点有误：功能早已实现，本条作废

- `pages/search/index.uvue` 已有热搜榜（`hotRank`），第 432 行还留着注释「V3 §6.8 历史 chip」，但**没有任何历史记录实现**（`grep historyChip|searchHistory|recentSearch` 为空）。
- 建议做法：本地存最近 10 条关键词，搜索页顶部做可删除的 chip；纯本地，无需后端。

### B3. 浏览历史（足迹）完全没有 ★★ → ✅ 已实现（见 §F）

- 全仓库检索「足迹 / history」零结果。用户看过一个商品后，除了重新搜索或翻收藏**没有路径回去**。
- 对「图片先说话、信息帮决策」的内容型 App 来说这是明显缺口。
- 建议做法：商品详情 `onLoad` 写入本地足迹（保留最近 100 条、去重、可按天分组），「我的」页加「浏览足迹」入口。

### B4. 没有分享能力 ★★ → ✅ 已实现（见 §F）

- 全仓库**没有 `onShareAppMessage`**，也没有任何「分享给好友 / 生成图片 / 复制商品链接」的动作；唯一的「复制链接」是商品详情「前往原店」在小程序/H5 下的降级（`pages/product/detail.uvue` 第 308 行）。
- 内容社区类 App 不做分享，等于放弃了唯一的自然增长渠道。
- 建议做法：至少先给小程序端补 `onShareAppMessage`（商品详情/动态详情/编辑专题三个页），App 端可后置。

### B5. 降价提醒无法订阅 ★★ → ✅ 按用户决策，降价相关内容已整体移除（见 §F）

- 有降价角标（`feed-item.badgeText`）、通知分类里有「降价」（`pages/notification/index.uvue` 第 47 行），但用户**没有任何入口去订阅某件已收藏商品的降价提醒**——收藏页的提醒按钮只基于发售批次（`reminderDateFor` 只认 release 的 startAt/endAt/balanceDueAt）。
- 建议做法：收藏页决策行增加「降价提醒」开关，落到 `Reminder` 的 `type`（可在 `TYPE_LABELS` 里加 `PRICE_DROP`）。

### B6. OCR / 多模态真实模型未接入 ★★★（产品自定最高优先级）

- `PRODUCT-DIRECTION-CURRENT.md` 把「订单截图 OCR / 多模态预填（尾款一键入库）」列为**高频优先**能力，标注「已实现基础闭环」。
- 代码侧确实闭环了（`services/ai/purchase-import-service.uts` 解析模型响应 + `pages/purchase/import.uvue`），且明确不伪造结果（Mock 会话下直接引导手动补全）。
- **缺的是真实模型配置**：目前没有任何模型 endpoint / key 的配置项（检索 `apiKey|baseUrl` 在 `config/` 下无结果）。
- 建议做法：在 `config/` 增加模型配置（endpoint + 是否启用），未配置时保持现在的「真实失败 + 引导手填」，配置后走真实调用。

### B7. 反馈历史无法查看 ★ → ✅ 已实现（见 §F）

- `domain/user/feedback-record.uts` 模型存在，`services/user-data/feedback-service.uts` 在离线时会「保存在本机待用户后续查证」，但**没有查看入口**（检索 `feedbackRecord|listFeedback` 在页面层为空）。
- 建议做法：「帮助与反馈」页底部加「我的反馈记录」列表（本地即可，标明提交状态：已提交/待补送）。

### B8. 同步状态对用户不可见 ★★

- 数据层做得很完整：离线写入会入队，联网后由 `App.uvue` 的 `onNetworkStatusChange → useSyncStore().syncNow()` 重放，失败还会降级存档。
- 但**没有任何页面展示同步状态**（检索 `useSyncStore` 在 `pages/`、`components/` 下零结果）。用户离线改了收藏/提醒，无从判断到底存没存上。
- 建议做法：「我的」页顶部（或设置组里）加一行状态：`已同步 / N 条待同步 / 同步失败（点击重试）`。
