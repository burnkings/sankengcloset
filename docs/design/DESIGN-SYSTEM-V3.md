## 0. 文档地位

本文件是三坑绮橱唯一生效的视觉与交互基线。代码、评审、截图验收和后续页面新增均以本文件为准。

- 旧版 Dashboard、统计 Hero、快捷入口、emoji 占位、白色长卡片堆叠等规则全部失效。
- 历史产品报告只保留事实与决策记录，不再拥有视觉规范权。
- 首页始终是三坑商品与内容 Feed，不恢复衣橱管理工具首页。
- “参考小红书”指学习图片优先、低噪声容器、双列浏览、搜索与频道前置、自然内容密度；不得复制其品牌红、商标、图标、文案、动效或页面像素。

## 1. 产品视觉定位

### 1.1 一句话

一个“图片先说话、信息帮决策、管理藏在需要处”的三坑兴趣消费 App。

### 1.2 关键词

图片优先、真实、轻盈、克制、暖感、可收藏、可决策、三坑专属。

### 1.3 视觉优先级

1. 商品、穿搭、品牌内容图片。
2. 用户此刻要做的判断：喜欢吗、多少钱、何时结束、是否已收藏。
3. 来源、状态、时间等可信信息。
4. 管理动作和辅助信息。

### 1.4 禁止恢复

- 首页 Dashboard、金额统计、衣橱数量、提醒汇总。
- 首页快捷入口宫格和“坑向分类”入口。
- 每页大面积粉色 Hero、渐变头图和统计胶囊。
- 无图文本大卡、长条白卡套长条白卡。
- emoji 作为图标、分类、占位或状态。
- 纯电商促销感：大红倒计时、优惠券、秒杀、站内付款暗示。
- 为“少女感”而堆粉色、紫色、花纹、描边、阴影和圆角。
- 在一张卡里同时放多个日期、标签、倒计时、点赞数、来源和操作。

## 2. 当前信息架构

### 2.1 一级导航

`首页 / 发现 / 收藏 / 动态 / 我的`

- 首页：商品、发售、编辑专题、穿搭的连续 Feed。
- 发现：搜索、专题、趋势、品牌与内容探索，不重复首页商品流。
- 收藏：用户保存的商品、动态与品牌；不保留合集分支。
- 动态：轻社区美图与穿搭；不扩展群聊、直播和无主题广场。
- 我的：身份、我的动态、衣橱、愿望单、订单、提醒、预算和设置。

## 3. 全局视觉 Token

### 3.1 颜色

品牌色保留三坑绮橱的莓玫色，不复制小红书品牌红。

| Token | 浅色 | 深色 | 用途 |
|---|---:|---:|---|
| `brand.primary` | `#D45F7E` | `#E47A96` | 主按钮、选中、收藏、链接 |
| `brand.strong` | `#B94767` | `#F08AA3` | 按压、价格重点 |
| `canvas` | `#FAF8F7` | `#141112` | 全局页面背景 |
| `surface` | `#FFFFFF` | `#211D1E` | 列表组、弹层、表单组 |
| `surface.subtle` | `#F5F2F3` | `#2B2628` | 搜索、输入、弱选中 |
| `text.primary` | `#262223` | `#F7F3F4` | 标题与正文 |
| `text.secondary` | `#686164` | `#BDB5B8` | 品牌、说明 |
| `text.tertiary` | `#989094` | `#8E8588` | 时间、辅助 |
| `border` | `#EEE9EB` | `#393335` | 分割线、输入边界 |
| `success` | `#4F9870` | `#69B98A` | 完成、有效 |
| `warning` | `#C47A45` | `#D99767` | 临期、待处理 |
| `danger` | `#C5535B` | `#E17880` | 删除、失败、过期 |
| `info` | `#667F9E` | `#86A0BF` | 中性提示 |

规则：

- 大面积只用 `canvas` 和 `surface`，品牌色面积单屏不超过约 10%。
- 价格可用 `brand.strong`，但正文和标题始终优先 `text.primary`。
- 类别 JK / Lolita / 汉服只在小标签、筛选选中和图标细节中使用各自低饱和色。
- 状态必须同时有文字或图标，不得只靠颜色。
- 禁止页面直接写十六进制或 `rgba()`；全部进入 token。

### 3.2 字体

使用系统中文字体；不下载装饰字体，不把品牌感建立在字体版权上。

| 语义 | 字号 | 行高 | 字重 | 用途 |
|---|---:|---:|---:|---|
| `display` | 44rpx | 56rpx | 700 | 只用于少量结果页/品牌字标 |
| `pageTitle` | 40rpx | 52rpx | 700 | 一级页标题 |
| `navTitle` | 34rpx | 44rpx | 600 | 二级导航标题 |
| `sectionTitle` | 32rpx | 44rpx | 600 | 区块标题 |
| `cardTitle` | 28rpx | 40rpx | 500/600 | 商品/内容标题，最多两行 |
| `body` | 28rpx | 44rpx | 400 | 正文、列表主文字 |
| `meta` | 24rpx | 34rpx | 400 | 品牌、时间、说明 |
| `caption` | 22rpx | 30rpx | 400/500 | 标签、极次要信息 |
| `price` | 30rpx | 38rpx | 600 | 双列卡价格 |
| `priceLarge` | 44rpx | 52rpx | 700 | 商品详情价格 |

规则：

- 页面中最多出现 4 个字号层级。
- 正文不使用 32rpx 作为默认，避免管理页面显得松散笨重。
- 标题左对齐；只有空状态、完成结果和单一确认弹窗可居中。
- 长标题最多两行；管理列表主标题一行，副标题一行。

### 3.3 间距

基础 4rpx 网格：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64rpx`。

| 语义 | 值 |
|---|---:|
| 普通页面左右边距 | 32rpx |
| 首页/圈子双列 Feed 左右边距 | 16rpx |
| 双列间距 | 12rpx |
| 卡片纵向间距 | 28rpx |
| Section 间距 | 40rpx |
| 标题到内容 | 20rpx |
| 列表组内左右边距 | 28rpx |
| 表单字段间距 | 28rpx |
| 页面底部安全留白 | TabBar/安全区 + 32rpx |

在 750rpx 画布下，双列固定宽度为 353rpx：`16 + 353 + 12 + 353 + 16 = 750`。UniApp X 关键布局不得依赖 `calc()`。

### 3.4 圆角、边框、阴影

| 元素 | 圆角 |
|---|---:|
| Feed 图片 | 12rpx |
| 商品/内容小卡容器 | 12rpx；通常不绘制外容器 |
| 列表组、表单组 | 20rpx |
| 大图、专题图 | 16rpx |
| 输入框 | 16rpx |
| 主按钮 | 16rpx |
| 弹窗/Bottom Sheet | 24rpx |
| 胶囊筛选 | full |

- Feed 卡默认无阴影、无描边、无白色底盒；图片与文字直接落在 `canvas`。
- 列表组默认白底 + 1rpx 内部分割线，无外阴影。
- 弹窗、底部操作面板、悬浮发布按钮可用一级轻阴影。
- 禁止每个元素都用 24–32rpx 大圆角。

### 3.5 图标

- 统一线性图标，视觉尺寸 40rpx，线宽约 2rpx。
- 主要导航图标 44rpx；行内图标 36–40rpx；辅助图标 28–32rpx。
- 任何图标点击热区不小于 88×88rpx。
- 空状态、图片失败、类别、衣物、删除、关闭均不使用 emoji。
- `AppIcon` 必须覆盖所有正式页面用到的图标；禁止在页面中临时画文本符号 `× / › / ✓ / ✕`。

## 4. 全局页面骨架

### 4.1 一级 Tab 页

```text
状态栏
页面标题 / 品牌字标 + 右侧动作
搜索（仅主任务需要时）
频道或筛选（可吸顶）
内容区
底部 TabBar + 安全区
```

- 首页头部最大内容高度 252rpx，不再使用 288rpx 以上固定大头部。
- 发现、收藏、圈子、我的使用 96rpx 紧凑页面标题区。
- 标题、搜索和频道只有需要的层级才出现，不能每页机械复制三层头部。

### 4.2 二级列表页

```text
返回 + 左对齐标题 + 可选右侧动作
搜索/筛选（有必要才显示）
内容列表
固定或悬浮新增动作
```

- Navbar 与系统状态栏、微信胶囊、安全区同步。
- 列表页返回后必须恢复滚动位置与筛选。
- 新增动作优先右上角文字或 88rpx FAB，不能两者同时出现。

### 4.3 详情页

```text
透明或实体导航
主图/内容
标题、品牌、价格、状态
决策信息区
详细信息分组
相关推荐（按需）
底部固定操作栏
```

- 商品详情主图接近屏幕边缘，信息区使用 32rpx 边距。
- 管理详情不强行放大图片，采用状态 + 时间线 + 字段分组。
- 底部操作栏必须避开安全区，内容不能被遮挡。

### 4.4 表单页

```text
返回 + 页面标题
图片/来源（可选）
分组字段
危险操作（编辑态）
底部固定主按钮
```

- 标签在输入框上方，必填标识与错误提示就近显示。
- 输入高度 88rpx，多行输入最小 176rpx。
- 日期、类别、状态使用统一选择器，不把下拉项伪装成普通输入。
- 保存时按钮进入 loading 且锁定，防止重复提交。
- 有未保存修改时返回必须确认。

## 5. 核心组件规范

### 5.1 `ProductCard`

- 双列宽 353rpx；图片 353×470rpx，接近 3:4。
- 卡片无白底盒、无阴影。
- 信息顺序：图片 → 品牌 → 标题 → 状态/截止（按需）→ 价格。
- 品牌 22rpx，标题 28rpx 两行，价格 30rpx。
- 收藏按钮位于图片右上安全区，44rpx 图标、72rpx 半透明触控底。
- 最多一枚状态；只有预售显示截止提示。
- 图片失败保持原比例，以中性底 + 图片图标 +“图片暂不可用”呈现。

### 5.2 `NoteCard`

- 圈子双列卡，图片可为 3:4 或 4:5，但同一数据源必须提供比例元数据，避免布局跳动。
- 图片下依次为标题两行、作者行、喜欢数。
- 作者头像 40rpx，昵称 22rpx；喜欢按钮热区 64rpx。
- 不在 Feed 直接显示评论、长正文或超过一个话题标签。

### 5.3 `ReleaseCard`

- 单列 16:9 大图或紧凑横卡；品牌、事件类型、开始/结束时间清晰。
- 主动作“提醒我”，次动作“查看商品”。
- 过期显示“已结束”，不使用高饱和倒计时。
- Overlay 只覆盖底部 35% 左右，不压暗整张图。

### 5.4 `EditorialCard`

- 单列 16:9 图 + 独立文字区。
- 标明“编辑整理 / 官方信息 / 用户投稿”及更新时间。
- 不把编辑内容伪装成商品卡。

### 5.5 `ManagementRow`

- 纵向列表行，最小高 112rpx；左侧可选 80×96rpx 缩略图。
- 中间为标题、状态/时间、最多一行金额；右侧只放箭头或一个主要状态。
- 使用分割线而不是每项一张卡。
- 滑动删除不作为唯一删除方式；详情页仍提供危险操作。

### 5.6 `SummaryStrip`

- 替代大面积 `V2StatsCard`。
- 同一行 2–3 个数据，透明背景或嵌入列表组顶部，高度不超过 112rpx。
- 只在衣橱、预算、订单、提醒等管理页出现；首页、发现、收藏、圈子禁用。

### 5.7 筛选与频道

- 一级频道：文字 + 4rpx 底部指示，支持横向滚动。
- 二级筛选：56rpx 胶囊，选中用品牌浅底 + 深色文字，不使用纯白字大色块。
- 筛选行可吸顶，但必须位于导航下方。
- 业务频道与品类筛选不得混在一行。

### 5.8 搜索

- 高 72rpx，`surface.subtle` 背景，16rpx 圆角。
- 首页为点击跳转型；搜索页为真实输入型。
- 搜索页显示历史、建议和结果状态；清除历史必须确认。
- 搜索进行时允许即时联想，结果列表请求防抖 250–350ms。

### 5.9 按钮

- 主按钮：品牌色实底，最小高 88rpx。
- 次按钮：中性浅底，不使用描边堆叠。
- 文字按钮：用于 Navbar、Section 右侧和轻操作。
- 危险按钮：危险色文字或浅底；只有最终确认可用实底危险色。
- 同一视图最多一个主按钮。

### 5.10 弹窗、Bottom Sheet、Toast

- 简单确认用 Dialog；选择多项、筛选、日期、外跳说明用 Bottom Sheet。
- 删除确认必须写明对象和后果，不使用笼统“确认删除”。
- Toast 位于状态栏/导航下方安全区域，最大宽 560rpx，1.8–2.4 秒自动消失。
- 成功、失败、离线和权限被拒绝必须有不同图标与文本。

## 6. 页面级布局与交互

### 6.1 首页 `pages/home/index.uvue`

布局：

1. 第一行：左侧“三坑绮橱”字标，右侧通知图标和微信胶囊避让。
2. 第二行：整行搜索框，文案“搜索商品、品牌或风格”。
3. 第三行：`推荐 / 新品 / 预约 / 降价 / 穿搭`，吸顶。
4. 内容：商品与穿搭按双列行（pair，353×470）组织；真实发售事件和编辑专题保持单列全宽行（single）；服务端混合 Feed 原始顺序原位保留，不拆散、不沉底。双列行内穿搭使用与 ProductCard 同尺寸的半宽卡（图 + 标题/副标题 overlay）。

交互：

- 下拉刷新保留当前频道；切频道清空旧列表并显示骨架，不闪空白。
- Feed 点击恢复回到原滚动位置。
- 商品收藏乐观更新，失败回滚并 Toast。
- `outfit` 没有真实内容时显示轻量空状态，禁止普通商品顶替。
- 首页不显示 JK/Lolita/汉服“坑向分类”、管理入口或用户统计。

### 6.2 发现 `pages/discover/index.uvue`

布局：紧凑标题“发现” → 搜索 → 编辑专题横卡 → 趋势话题横向列表 → 品牌索引/发售日历入口。

- 不重复首页双列商品列表。
- JK/Lolita/汉服可以作为发现筛选或专题标签，但不是首页快捷入口。
- 所有专题入口必须有真实落地页；未完成入口不展示。

### 6.3 收藏 `pages/favorites/index.uvue`

布局：标题 → `商品 / 穿搭 / 品牌 / 合集` 频道 → 对应内容。

- 商品用同一 `ProductCard`；穿搭用 `NoteCard`；品牌用紧凑列表；合集用 2×2 拼图卡。
- 空状态只描述当前频道，并提供“去发现”主动作。
- 取消收藏立即移出当前列表，提供短时“撤销”。
- Mock 登录只写本地，不发送假 Token。

### 6.4 圈子 `pages/community/index.uvue`

布局：标题“圈子” + 右侧“发布” → `推荐 / 最新 / JK / Lolita / 汉服` → 双列穿搭笔记。

- 帖子卡显示图片、标题、作者、喜欢数；不做商品价格卡。
- 发布入口只保留一个。
- 空列表、接口失败、离线和未登录分别显示状态，不得白屏。
- Mock 点赞本地保存；真实登录才访问受保护接口。

### 6.5 我的动态 `pages/community/mine.uvue`

- 标准二级 Navbar；顶部用 `已发布 / 本地草稿` 分段控制。
- 内容使用紧凑列表或双列预览；草稿明确标“仅本机”。
- 支持继续编辑和删除；删除先确认。
- 无动态时引导发布，不推荐假内容。

### 6.6 我的 `pages/profile/index.uvue`

布局：

1. 无外层卡片的紧凑个人头部：头像、昵称、Mock/同步状态、编辑入口。
2. “我的内容”：收藏、动态。
3. “管理中心”：衣橱、愿望单、购买记录、提醒、预算，使用一致图标网格或分组行。
4. “设置与支持”：内容偏好、外观、通知、关于。

- 不展示后台式大数字统计。
- Mock 账号必须持续显示“Mock 内测 · 数据保存在本机”。
- 设置列表使用 `ListGroup + ListRow`，不做一整条大白卡分散两端。

### 6.7 通知 `pages/notification/index.uvue`

- Navbar：返回、标题“通知”、右侧“全部已读”。
- 筛选：全部 / 未读 / 发售 / 互动 / 系统。
- 行结构：类型图标、标题、摘要、时间、未读点；同日可分组。
- 点击后标记已读并跳转真实目标；无目标则留在通知详情/说明。

### 6.8 搜索 `pages/search/index.uvue`

- 顶部固定真实输入框 +“取消”。
- 未输入：搜索历史、最近查看、趋势词；不显示假热搜。
- 输入中：防抖联想；清除按钮可用。
- 结果：`综合 / 商品 / 穿搭 / 品牌`；商品双列、穿搭双列、品牌列表。
- 加载、空、失败和分页底部状态齐全。

### 6.9 发布 `pages/share/create.uvue`

- 图片选择区优先，支持 1–9 张预览、排序和删除。
- 标题/说明 → 坑向 → 话题 → 关联商品/衣橱单品 → 可见范围。
- 底部固定“发布”；Mock 会话写本地草稿并明确提示。
- 图片权限拒绝、上传失败、退出未保存均有恢复路径。

### 6.10 商品详情 `pages/product/detail.uvue`

- 顶部 3:4 主图/轮播接近全宽；Navbar 浮在主图上并保证对比。
- 信息顺序：品牌 → 商品名 → 当前价/原价 → 状态/截止 → 来源与更新时间。
- “与衣橱搭配度”作为一条辅助决策模块，不占首屏大卡；无衣橱数据时解释如何获得结果。
- 底部固定：收藏 / 设置提醒 / 前往官方渠道。
- “记入购买”放在外跳返回后的确认或更多操作，不制造站内交易感。

### 6.11 编辑专题 `pages/editorial/detail.uvue`

- 16:9 头图、标题、摘要、来源/更新时间、正文段落。
- 相关商品使用双列 `ProductCard`，标题为“专题商品”。
- 文章段落宽度 32rpx 边距，行高 1.65；不使用大段居中文字。

### 6.12 衣橱 `pages/wardrobe/index.uvue`

- Navbar + 搜索；二级筛选为全部/JK/Lolita/汉服/其他。
- `SummaryStrip` 只显示总件数和当前筛选数，不展示 Dashboard 式统计卡。
- 默认双列图库；图片比例与公共商品卡统一，但信息显示穿着状态而非发售状态。
- 新增用单一 FAB；空状态引导“添加第一件”。

### 6.13 衣橱编辑 `pages/wardrobe/edit.uvue`

- 首屏图片选择；基础信息、分类尺码、购买信息、标签备注分组。
- 标签在输入上方；类别用 Segmented/Sheet，不用自由文本。
- 编辑态删除置于页面末尾“危险操作”，与保存分离。

### 6.14 月度预算 `pages/budget/index.uvue`

- 顶部月份切换；主模块为“预算使用进度”，不是多张统计卡。
- 依次显示预算、已支付、待支付、剩余；金额单位统一为元显示。
- 超预算使用警告色和具体差额，不使用羞辱/恐吓文案。
- 修改预算使用底部 Sheet 或单独编辑区，保存后即时更新。

### 6.15 购买记录 `pages/purchase/index.uvue`

- Navbar + `全部 / 待付 / 进行中 / 已完成 / 已取消`。
- `SummaryStrip` 只保留本月已支付和待付尾款。
- 列表按“本月 / 往期”分组，每行突出商品、状态、下一个日期和待付金额。
- 新增与订单导入不能同时占两个 FAB；FAB 点开轻量动作菜单。

### 6.16 订单详情 `pages/purchase/detail.uvue`

- 顶部状态和商品摘要；中段金额分解；下段时间线与关联提醒。
- 状态流转为主要动作，编辑/删除放 Navbar 更多菜单。
- 已到货允许“加入衣橱”；必须防重复并提示已关联对象。

### 6.17 订单编辑 `pages/purchase/edit.uvue`

- 基本信息、金额、日期、补充分组。
- 输入以元，存储以分；字段旁不重复显示“元”造成混淆。
- 实时校验总额、定金、已支付之间的关系。
- 底部保存锁定防连点；失败保留已填内容。

### 6.18 订单导入 `pages/purchase/import.uvue`

- 页面按 1 选择来源 → 2 识别/解析 → 3 人工确认 三步展示。
- 截图上传是主入口，链接粘贴是次入口，手动填写始终可达。
- 未配置真实 OCR 时明确提示并进入手动补全，禁止伪造识别结果。
- 确认后只创建一笔购买记录，并同步尾款提醒。

### 6.19 愿望单 `pages/wishlist/index.uvue`

- 与“收藏”明确区分：愿望单是购买决策管道，不是内容收藏夹。
- `种草 / 观望 / 决定买 / 已买 / 搁置 / 拔草` 使用二级筛选。
- 双列卡显示商品、预估价、状态；不显示公共 Feed 的来源与截止信息。
- 顶部只保留心愿总数和待买数量的紧凑摘要。

### 6.20 心愿详情 `pages/wishlist/detail.uvue`

- 大图 + 商品/品牌/预估价；状态进度；备注和链接。
- 主动作随状态变化；“生成购买记录”必须确认且防重复。
- 编辑在 Navbar；删除在更多菜单或页面末尾。

### 6.21 心愿编辑 `pages/wishlist/edit.uvue`

- 图片、商品信息、预估价格、状态、链接、备注分组。
- 状态不平铺六个大按钮；使用 Sheet 或横向可滚动选择。
- 链接解析失败不清空用户输入。

### 6.22 提醒 `pages/reminder/index.uvue`

- 筛选：待办 / 今日 / 本周 / 已完成 / 已过期。
- 顶部紧凑摘要只显示待办、今日、过期。
- 列表按日期分组，左侧时间或状态点形成轻时间轴。
- 快速完成提供撤销；删除不与完成共用点击区。

### 6.23 提醒编辑 `pages/reminder/edit.uvue`

- 基础信息、时间、关联对象、备注、状态分组。
- 类型选择使用统一图标，不保留 `👗 / ✓ / ✕ / ›`。
- 关联衣橱单品用 Bottom Sheet 搜索与选择。
- 未保存离开确认、保存锁和删除确认统一复用公共组件。

### 6.24 内容偏好 `pages/preferences/index.uvue`

- 标题改为“内容偏好”，说明“用于首页推荐与发现排序”。
- JK/Lolita/汉服支持多选；可补充风格、价位、品牌偏好。
- 选择即时本地保存并显示轻反馈；不是一个只有三枚静态标签的页面。

### 6.25 设置 `pages/preferences/appearance.uvue`、`notification.uvue`

- 外观：跟随系统 / 浅色 / 深色三态单选；可见预览，不使用单一开关代替三态。
- 通知：总开关 + 发售/尾款/到货/互动分项；权限被系统关闭时提供去设置说明。
- 所有开关使用整行点击热区，副标题解释影响。

### 6.26 关于与协议 `pages/about/index.uvue`、`legal.uvue`

- 关于页：Logo、名称、版本、定位一句话；协议与隐私使用分组列表。
- 协议页：清晰标题、更新时间、正文、目录锚点；正文 28rpx/46rpx。
- 不把版权信息做成大卡；放页面底部弱文本。

## 7. 全局状态与反馈

每个请求型页面必须具备：

| 状态 | 规范 |
|---|---|
| 首次加载 | 与真实布局同形骨架，不使用全屏转圈 |
| 下拉刷新 | 保留旧内容，顶部刷新，不白屏 |
| 加载更多 | 列表底部 24rpx 文案/轻指示 |
| 空状态 | 线性图标 + 一句原因 + 一个有效动作 |
| 错误 | 说明失败对象 + 重试；保留可用旧数据 |
| 离线 | 明确离线，可继续访问本地个人数据 |
| 图片失败 | 保持比例与布局，不出现塌陷 |
| 禁用 | 对比度仍可读，同时阻止重复触发 |

## 8. 交互一致性

- 点击态：160ms 内，透明度 0.86 或中性背景变化；列表滚动中不执行复杂缩放。
- 页面转场遵循系统；不自制全屏花哨过渡。
- 收藏/点赞可乐观更新，失败必须回滚。
- 删除、发布、保存、导入确认必须幂等或锁定。
- 外跳购买前显示渠道；本应用不出现“立即支付”“加入购物车”。
- 所有视觉可点击元素必须有真实事件、禁用态或隐藏，不留空函数。
- 页面返回必须保留上级列表筛选、频道与滚动位置。

## 9. Dark Mode

- 深色模式不是简单反转；图片保持原色，canvas/surface/文字/边框/输入/弹层/TabBar 全部同步。
- 深色页面避免纯黑和纯白，使用暖黑背景和柔白文字。
- 品牌色在深色下提升亮度，保证按钮与文字对比。
- Skeleton、遮罩、Toast、系统 Chrome 同步主题。
- 首帧读取持久化主题，禁止先浅后深闪烁。

## 10. UniApp X / Android 实现红线

- App：Vapor + `list-view/list-item` + 分页；小程序：`scroll-view`/页面滚动 + 分页。
- 长列表必须有明确像素高度；禁止 `height: 0 + flex` 猜测可用空间。
- 关键布局禁用 CSS Grid、`gap` 和 `calc()`；使用固定 rpx、flex、margin。
- 主 `v-for` 只放在 App `list-item` 复用层；稳定 `key`；复用时重置组件内部状态。
- 不在 computed 中反复创建 Store；Store 在模块/页面初始化一次。
- 不使用 DOM、Window、localStorage、浏览器事件等 Web 专属 API。
- UTS 复杂返回值显式类型；避免批量引入不受 Android 支持的联合类型/泛型写法。
- 图片列表请求缩略图，默认 lazy-load；累计 100 条后控制内存或分页替换。
- 横向频道可嵌套滚动，禁止多层纵向 `scroll-view`。
- 微信胶囊、Android 状态栏、底部手势区均用真实运行时尺寸适配。
- 不修改 `vendor`、`dist`、`unpackage` 或其他编译产物。

## 14. 设计验收标准

### 14.1 全局

- 28 个用户页面及其所有 loading/empty/error/disabled 状态使用同一 Token 和组件体系。
- 无正式 UI emoji、硬编码颜色、重复页面样式和空点击事件。
- 一级页无大 Hero、无 Dashboard、无统计胶囊堆叠。
- Feed 卡弱容器，管理页分组清楚，表单字段与底部操作一致。
- 浅/深色完整同步；长文字、无图、弱网、离线不白屏。

### 14.2 首页

- 首屏在搜索和频道后直接出现真实商品/内容。
- 商品双列边距、列宽、图片比例和文字层级一致。
- 首页无“坑向分类”、衣橱/订单统计或快捷入口。
- `price_drop`、`outfit` 不用普通商品伪装。

### 14.3 管理中心

- 订单金额显示单位正确；保存、导入、转订单、入橱均防重复。
- 提醒、愿望、衣橱和购买页不再机械使用同一张统计大卡。
- 删除、返回未保存、权限失败均有统一反馈。

### 14.4 工程

- `node scripts/check-v24-remote-runtime.js` 通过。
- `node scripts/check-v25-android-beta.js` 通过。
- `node scripts/check.js` 通过。
- 微信构建与 Android 构建分开记录。
- Android 真机启动、滚动、页面返回和深色切换有明确结果。
- 删除文件前有零引用证据；不修改 main、不 force push。

## 15. 参考边界
