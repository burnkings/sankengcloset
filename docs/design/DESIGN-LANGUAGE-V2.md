# 三坑绮橱 Design Language v2.4

> Product V2 内容生态设计规范  
> 状态：生效  
> 日期：2026-07-14  
> 所有 Product V2 新页面、新组件必须遵循本规范。现有 `theme/**`、基础组件和布局系统优先复用。

---

## 1. 设计目标

### 1.1 关键词

**收藏感 · 高级感 · 展示感 · 消费欲 · 治愈 · 有氛围 · 内容优先 · 图片优先**

视觉参考可以借鉴小红书的留白、得物的商品信息密度、Pinterest 的图片编排和 Lemon8 的生活方式氛围，但不得照搬任何单一产品。

### 1.2 不是这些

- 不是 Dashboard、后台管理、ERP 或 CRUD 工具首页。
- 不是白蓝工具风格，也不是密集宫格菜单。
- 不是传统电商首页：不堆优惠券、秒杀、弹窗和促销红色。
- 不是泛娱乐社区：内容始终围绕商品、品牌、系列和穿搭。
- “不采用 Material Design 视觉风格”不等于拒绝平台可用性规范；触控尺寸、返回行为、安全区和无障碍仍应遵循平台习惯。

## 2. Product V2 页面分类

| 页面类型 | 首屏核心 | Hero 规则 | 示例 |
|---|---|---|---|
| 内容首页 | 搜索、频道、首条内容 | **禁止统计型 Hero**；默认无 Hero | 首页 Feed |
| 发现页 | 搜索、分类、趋势、日历 | 无大 Hero | 发现、搜索结果 |
| AI 页 | 明确任务卡和最近任务 | 可使用轻量氛围头图，不显示统计 | 绮灵 AI |
| 收藏页 | 状态频道、合集、商品 | 可使用紧凑情绪标题，禁止统计胶囊 | 收藏 |
| 我的页 | 身份、创作、管理中心 | 可使用紧凑个人头部 | 我的 |
| 管理页 | 当前任务与筛选 | 原 Hero 可保留，但应收敛高度 | 订单、提醒、衣橱 |
| 详情页 | 图片、标题、关键信息、决策动作 | 无 Hero | 商品、品牌、穿搭详情 |
| 编辑页 | 表单与确认 | 无 Hero | 订单编辑、穿搭发布 |

旧规范中“首页必须有 Hero”和“所有管理页必须有统计胶囊”的要求取消。

## 3. 一级导航与页面骨架

### 3.1 一级导航

Product V2 使用五个一级目的地：

```text
首页 / 发现 / 绮灵 AI / 收藏 / 我的
```

- 每个 Tab 保持独立滚动位置和页面状态。
- Tab 文案不使用“管理”“列表”“控制台”等后台词汇。
- 绮灵 AI 是真实目的地，不做悬浮噱头按钮。
- 订单、提醒、衣橱和预算进入“我的 > 管理中心”。

### 3.2 首页骨架

```text
┌─────────────────────────────┐
│ 品牌标识   搜索框       消息 │
├─────────────────────────────┤
│ 推荐 关注 JK Lolita 汉服    │
├─────────────────────────────┤
│ 首条内容 / 今日重要预约      │
│ 商品、品牌、穿搭混合 Feed    │
│ 商品、品牌、穿搭混合 Feed    │
└─────────────────────────────┘
```

首页禁止：

- 欢迎语大 Hero。
- 衣橱、消费、提醒统计。
- 快捷入口九宫格。
- “我的提醒”“我的种草”等个人管理卡。
- 固定占据首屏的大 Banner。

### 3.3 搜索规则

旧规范“禁止独立搜索栏占一整行”取消。

- 首页允许紧凑搜索框与品牌标识同排。
- 发现页允许搜索框占据主要宽度，因为搜索是页面主任务。
- 搜索框高度建议 72–80rpx，圆角使用 `full` 或大圆角。
- 搜索页聚焦后可以进入整行输入状态。

## 4. 布局与间距

### 4.1 基础间距

- 页面水平间距：`semanticSpacing.pageHorizontal`，当前为 32rpx。
- 内容卡间距：16–24rpx，根据单列/双列决定。
- Section 间距：32–48rpx。
- TabBar 上方安全留白：不少于 `semanticSpacing.safeBottom`。
- 信息密度应通过真实图片和排版提升，不通过缩小字号或堆叠标签提升。

### 4.2 Feed 布局

MVP 不直接采用高度不可控的真瀑布流。视觉与渲染结构分开处理：

1. App 端使用 Vapor + `list-view/list-item` 复用；双列通过“每个 list-item 表示一行、行内两个固定卡位”实现。
2. 小程序端使用同一份 uvue 业务代码编译，采用分页追加和固定比例双列；小程序不运行 App 原生 Vapor 渲染引擎。
3. 商品/穿搭图片统一 3:4 或 4:5，单列品牌动态、预约、降价和编辑专题独立编排。
4. 混合 Feed 由明确的卡型和数据类型驱动，避免双列中直接插入超宽卡导致跳动。

只有在 AppX/Android `list-view` 复用和小程序分页长列表真机验证通过后，才允许启用可变高度瀑布流。

### 4.3 竞品首页取舍

竞品“浪漫裙匣”首页可借鉴：

- 首屏直接进入图片内容，不展示个人统计。
- 搜索、频道和双列商品图形成清晰浏览节奏。
- 暖白底、深棕文字和低饱和品牌感适合三坑审美。
- 图片明显大于文字，能快速制造消费与收藏欲望。

不得照搬：

- “全部/最新/本周/本月/图透/定金/尾款”等全部堆在一级频道，信息过载。
- 商品卡同时争抢展示定金、尾款、倒计时、价格、喜欢数和多重边框。
- 过小文字、过浅灰色和辨识度不足的底部图标。
- 其他页面的大面积空白、传统设置卡和缺少内容承接的空状态。

三坑绮橱首页应做到：保留竞品的图片吸引力，减少噪音，并用结构化商品详情、收藏状态、AI 决策与管理闭环形成超越。

## 5. 图片系统

### 5.1 Image First Rule

| 场景 | 推荐比例 | 说明 |
|---|---|---|
| 首页商品卡 | 3:4 | 服饰主体展示 |
| 穿搭卡 | 4:5 或 3:4 | 保留全身构图 |
| 商品详情主图 | 3:4，可轮播 | 不强制裁切原图 |
| 品牌/系列专题 | 16:9 或 3:2 | 氛围横图 |
| 预约/发售事件 | 16:9 | 海报与时间信息 |
| 衣橱 Grid | 3:4 | 与公共商品卡保持统一视觉 |
| 列表缩略图 | 4:5 | 适合服饰纵向构图 |

旧版 Wishlist、Wardrobe 使用约 2:1 横向封面的规则废止。

### 5.2 加载与失败

- 使用 `AppImage`，开启 lazy-load、骨架占位和错误回退。
- 占位使用中性骨架和品牌浅色，不使用 emoji 作为正式占位。
- 错误态使用统一线性图片图标与“重新加载”，不使用 `🖼️`。
- 远程图片必须请求缩略图尺寸；不得在 Feed 直接加载原图。
- 列表滚动时减少渐变、阴影和实时模糊计算。

## 6. 内容卡系统

### 6.1 ProductCard

```text
┌──────────────────────┐
│                      │
│      3:4 商品图       │
│                 收藏 │
├──────────────────────┤
│ 品牌                 │
│ 商品名称（最多两行）  │
│ ¥价格     预约/现货   │
└──────────────────────┘
```

- 品牌是弱标题，商品名是主标题。
- 价格与状态同层，但状态不得用高饱和大色块。
- 收藏按钮覆盖在图片安全区，必须有半透明底保证可读。
- 标签最多显示 2 个，多余信息进入详情。

### 6.2 ReleaseEventCard

- 单列横卡或大图卡。
- 明确品牌、事件类型、开始/结束时间、信息更新时间。
- 主动作是“提醒我”，次动作是“查看商品”。
- 过期事件自动降权并显示已结束，不继续营造紧迫感。

### 6.3 OutfitCard

- 图片为第一视觉中心。
- 展示作者、风格和最多 3 个关联单品。
- MVP 支持喜欢、收藏、分享；评论与私聊在治理能力完成后开放。

### 6.4 BrandUpdateCard

- 明确“官方信息”“编辑整理”或“用户投稿”来源。
- 官方信息可高置信自动发布，仍显示来源和抓取/更新时间。

### 6.5 AIRecommendationCard

- 必须展示简短推荐理由。
- 提供“不感兴趣”和“为什么推荐”。
- 不使用“绝对适合”“一定会涨/降”等确定性措辞。

## 7. 颜色、字体与层级

### 7.1 颜色

- 继续使用现有 `brand` 蔷薇粉、`accent` 薰衣草紫和 JK/Lolita/汉服分类色。
- 页面大面积背景优先使用 neutral；品牌色用于操作、选中和小面积氛围。
- 不在同一屏同时使用多组高饱和渐变。
- 商业内容、官方内容、AI 内容使用不同的文字标识，不只依赖颜色。
- 禁止硬编码颜色，统一从 `theme/tokens/colors.uts` 获取。

### 7.2 字体

| 用途 | 字号 | 字重 | 行数 |
|---|---|---|---|
| 页面标题 | `fontSize.xl` | bold | 1 |
| Section 标题 | `fontSize.lg` | semibold | 1 |
| 卡片标题 | `fontSize.base` | semibold | 最多 2 |
| 正文 | `fontSize.base` | regular | 按场景 |
| 辅助信息 | `fontSize.sm` | regular | 最多 2 |
| 标签 | `fontSize.xs` | medium | 1 |

正文和辅助文本必须有可读对比度，不用过浅灰色营造“高级感”。

## 8. Tag、Badge 与图标

- 状态标签继续使用 `statusPill(color)`，背景控制在低饱和透明色。
- 筛选使用 `AppTag` 的 `TAG_CHIP`。
- 分类使用 `TAG_CATEGORY`。
- 商品卡标签最多 2 个；管理卡允许最多 3 个。
- 正式界面使用统一线性图标，不使用 emoji 充当功能图标、分类图标或空状态。
- 若暂时没有图标资产，使用纯文字按钮，不用 emoji 代替。

---

## 9. 详情页与决策操作

商品详情页底部固定决策栏：

```text
收藏 / 问绮灵 / 前往购买
```

- “前往购买”必须明确是跳转外部应用或官方渠道。
- 本应用不展示“加入购物车”“立即支付”等会造成站内交易误解的文案。
- 外跳前展示目标渠道；返回 App 后可询问是否记录为已购买，但不得默认创建订单。

## 10. 社区交互边界

第一阶段只包含：

- 发布穿搭/美图。
- 喜欢、收藏、分享。
- 关联商品、品牌、系列和衣橱单品。

后期可增加：

- 评论与回复。
- 一对一私聊。

不规划群聊、群组、直播或无主题动态广场。评论和私聊上线前必须具备举报、拉黑、审核、反骚扰和未成年人保护。

---

## 11. 动效与反馈

- 收藏、关注、Tab 切换使用 `duration.fast/normal`。
- Feed 首屏不做逐卡复杂入场动画。
- 图片加载只使用轻量淡入，避免列表同时执行大量动画。
- 支持“减少动效”设置。
- 所有异步操作必须有 loading、成功、失败和可重试状态。

---

## 12. Dark Mode 与无障碍

- 继续复用 `neutralDark`、`shadowDark` 与 `use-theme.uts`。
- Product V2 的“我的 > 设置”必须提供跟随系统、浅色、深色入口。
- 触控目标建议不小于 44×44 CSS px 对应区域。
- 关键信息不能只用颜色表达。
- 图片发布与品牌内容支持替代文本/内容描述字段。

## 13. AppX / Android 性能与 Vapor 规范

### 13.1 编译模式决策

- Product V2 的 App 目标默认启用 `uni-app-x.vapor: true`。
- Android 使用 HBuilderX 5.21+ Vapor 内测能力；固定编译器版本，不随意升级。
- iOS 5.11+、HarmonyOS 5.0+ 使用 Vapor。
- 同一份 Vapor uvue 页面可以编译至微信小程序与 Web，但这些平台不使用 App 原生 Vapor 渲染引擎，仍需单独验证运行性能。
- 不以 mp-weixin 编译日志显示“VDOM模式”否定 App 端 Vapor 配置。

### 13.2 Vapor 不替代列表复用

Vapor 解决 VNode 创建、Diff 和视图更新开销；列表复用解决屏外节点、数据对象和图片长期驻留。正式图片 Feed 必须组合使用：

```text
App：Vapor + list-view + list-item + 分页 API
小程序：分页 API + 固定双列 + lazy-load + 累积数据控制
```

App Vapor 的 `list-view` 要求：

- 仅在第一个 `list-item` 上使用主 `v-for`。
- 必须提供稳定 `:key`。
- 复用卡片的内部状态通过 `onReuse/onRecycle` 重置。
- 不在 `list-item` 上使用 margin，间距由内部容器或 padding 提供。
- Feed 卡组件不得保存未与当前绑定数据同步的隐式状态。

### 13.3 真机门禁

内容 Feed 开发必须完成长列表技术验证：

- 30、100、300 张卡片的 Android 真机滚动测试。
- 首屏加载、快速滑动、返回位置恢复、图片失败和弱网测试。
- App 比较 Vapor `list-view` 复用；小程序验证分页 `scroll-view` 或页面滚动策略。
- 建立缩略图、分页、预取、内存与缓存上限。
- 未验证前不实现可变高度瀑布流。

Android 性能只能以 release 正式包测试；debug 结果不作为上线结论。配置已打开不等于性能已经改善，必须保留真机数据。

## 15. 禁止事项

1. 禁止把首页重新做成统计、提醒和快捷入口集合。
2. 禁止首页大面积 Hero 与水平数字统计条。
3. 禁止把 ProductCard 直接等同于 WardrobeCard。
4. 禁止正式 UI 使用 emoji 图标和 emoji 占位。
5. 禁止硬编码颜色、阴影、圆角和页面间距。
6. 禁止内联复制 chipStyle、emptyStyle 等公共样式。
7. 禁止 Feed 一次全量渲染所有数据。
8. 禁止在 Feed 直接请求原尺寸图片。
9. 禁止没有来源和更新时间的价格/发售信息。
10. 禁止使用“站内购买”“立即支付”等造成交易闭环误解的文案。
11. 禁止为了视觉接近参考应用而牺牲 Android 性能、安全区和可访问性。

## 16. 设计验收清单

- 首屏是否首先展示内容，而非用户统计？
- 用户是否能在两步内完成收藏或查看商品详情？
- 图片是否使用正确比例和缩略尺寸？
- 是否存在 emoji、硬编码颜色或重复内联样式？
- 官方、编辑、用户、AI、商业内容是否可区分？
- 外跳购买是否清楚说明目标渠道？
- 深色模式、弱网、空状态、失败态是否可用？
- Android 长列表和图片加载是否有真机结果？
- 是否复用了现有 Token、基础组件和布局系统？

## 17. Final Experience 收敛规则

### 17.1 首页筛选

- 一级业务频道固定为：推荐、新品、预约、降价、穿搭。
- 二级品类固定为：全部、JK、Lolita、汉服；采用弱化胶囊并随内容滚动，不长期占用固定导航高度。
- 业务状态与服饰品类不得再次混排在同一行。

### 17.2 商品卡决策信息

- 卡片信息顺序统一为：图片 → 品牌 → 商品名 → 截止提示（按需）→ 价格。
- 单卡最多出现一个阶段状态和一条截止提示，不同时堆叠点赞数、来源、多个日期和多枚标签。
- 商品状态不再悬浮为图片右上角的浅色圆形/胶囊；统一放入信息区，用“色点 + 文字”表达，避免遮挡商品主体。
- 预售商品显示“距结束”，普通现货与新品不制造虚假紧迫感。
- 价格与小字号交互文字使用具备可读对比度的深阶品牌色；浅阶品牌色只作为背景。

### 17.3 页面节奏

- 首页负责新品、品牌动态、官方发售和穿搭内容的连续 Feed；发现页负责分类入口、晒搭社区、品牌导航、发售日历和趋势话题。
- 发现页不再重复陈列首页的双列商品与降价商品列表；需要商品价格决策时回到首页或搜索页。
- 绮灵 AI 先承接最近任务，再展示核心能力和次级能力；不得恢复为六个等权后台式入口。
- 收藏无行为数据时使用“可能喜欢/根据品类偏好”，不得伪装成已经训练完成的个性化推荐。

### 17.4 交易边界

- 商品详情最终动作保持：收藏 / 问绮灵 / 前往官方渠道。
- 不出现“立即付定金”“立即补尾款”“加入购物车”等站内交易暗示。
- 外跳后只有在用户确认时才生成购买记录。

### 17.5 AppX 落地边界

- 375px 标注只用于设计换算；正式实现使用 rpx、flex 和最大内容宽度。
- 微信端不得依赖 `gap`、`calc()` 或 CSS Grid 完成关键布局。
- 公共卡片、筛选和页面边距必须来自组件与 token，禁止五个一级页面分别复制。

### 17.6 标题与交互

- 微信自定义导航中，页面标题左对齐是默认方案，可避开右侧胶囊并建立稳定阅读起点。
- 区块标题保持左对齐；只有空状态、完成结果和单一确认场景允许居中标题。
- 区块标题必须说明内容职责，禁止每个卡片重复显示同名标题，也禁止标题紧贴屏幕边缘。
- 所有视觉上可点击的搜索框、卡片、操作文字必须有真实反馈；禁止保留空事件函数。

### 17.7 偏好、主题与社区

- “内容偏好”必须明确说明用于首页推荐，支持多选并持久化；不得只展示 JK/Lolita/汉服三个静态标签。
- 深色模式必须持久化，并同步页面背景、卡片、输入框、文字、分割线和底部 Tab；不得只把页面背景改黑。
- 晒搭模块属于轻社区：V2 先支持选图、说明、坑向和本地预览；接入内容服务后再开放公开发布、点赞与评论。
- JK、Lolita、汉服使用原创的水手襟/裙装/交领图标，不再使用通用衬衫、蝴蝶结和折扇替代。

## 18. V2.5 平台与导航决策（2026-07-17）

### 平台优先级

- P0：微信小程序与 Android App 同轮开发、同轮验收。页面不得依赖仅微信可用的布局偶然行为。
- P1：HarmonyOS 保留编译兼容性与安全区方案，功能接口不得主动封死。
- P2：iOS 最后进入真机精修，但数据模型、路由和视觉 Token 与 Android 共用。
- 关键交互必须使用 UniApp X/UTS 与 `uni.*` 跨端 API；微信专属能力使用条件编译隔离。

### 一级导航

`首页 / 发现 / 绮灵AI / 晒搭 / 我的`

- 首页：个性化内容流与商品/发售动态。
- 发现：品牌目录、编辑专题、完整发售日历和趋势话题，不重复首页坑向筛选。
- 绮灵AI：图片识款、衣橱搭配、平替雷达、收藏画像、预算守门、发售雷达，六项能力输入与输出必须不同。
- 晒搭：轻内容社区；发布照片时显式选择坑向和话题，话题由内容产生。
- 我的：收藏、衣橱、购买记录、提醒、预算、登录与设置。收藏不再独占一级导航。

### 真机兼容红线

- `list-view` 必须使用计算后的明确像素高度，不用 `height: 0 + flex` 猜测可用空间。
- 关键布局禁用 `gap`、`calc()` 和 CSS Grid；使用明确宽度与 margin。
- 主题在模块首次求值时同步读取，避免页面先浅色后深色的首帧闪烁。
- 状态栏、导航栏、页面背景和 TabBar 必须同步主题色。
